What changed

Scroll. Almost every package behaves exactly as it did before, and that is the point — the silence is what gives the exceptions their weight.

A · in a path is something that varies between runs and means nothing — a temp directory, a pid, a cache key — normalised away so two identical runs compare equal. Anything left that differs is real.

What watching behaviour cannot see

This one changed no observable behaviour at all — it touched nothing new and called nobody. The computation changed. It is here because a tool that only watches behaviour would miss it, and saying so is more useful than pretending otherwise.

Why this could not exist a year ago

You cannot know what a package does without running it, and nobody could afford to run twelve hundred of them in isolation. Forking a live machine now costs a fraction of a cent, so the arithmetic changed — and the timing matters: npm disabled install scripts by default in July 2026, and within six days an attack detonated at import time instead. Reading the source was already behind. Watching it run is the only thing that sees this.

What is real here

Running for real

  • The transcript schema, normalisation, and the behavioural differ — pure and tested
  • Pair running: two twins per package from one checkpoint, waves, every branch released
  • Severity by rules, not by judgement — a model can explain a finding, never escalate one
  • Triage economics: 7 model calls for a 1,214-package tree
  • One observer that has actually watched something: nodert installs real packages from the real registry and reports what they reached for. It found that picocolors 1.1.1 reads NO_COLOR, CI and FORCE_COLOR, which 1.0.0 did not.
  • This interface, driven by an actual run

Simulated today

  • This page's run — adapters/simulated.js, a fixed corpus, no network, so the demo is deterministic and anyone can check it
  • The kernel-level strategies (eBPF, egress proxy): written, none has watched a real kernel yet
  • Nemotron and Tavily fall back to a local stand-in with no key set — and every simulated answer says so, right where it appears

What this cannot do

A package that was already malicious in the version you had. This compares you to your previous version, not to “good”. Something exfiltrating since before you installed it looks, to a differential tool, perfectly well behaved. It catches the moment a package turns — which is how most supply-chain compromises arrive — not a clean-room audit.

A payload that waits. A time bomb, or something gated on a CI variable, does not appear in the transcript at all. A package that did nothing because it was waiting looks exactly like one that did nothing because it is honest.

A change in what the code computes. That is the money-fmt section above.

A package that notices it is being watched. Each twin is its own microVM rather than a container, which raises the cost of detection. It does not eliminate it.

And one thing it now does see. 2026's attacks ship a decoder rather than a payload, and a string becoming a function never becomes a syscall — so a kernel tracer watches the process and misses the thought. The nodert strategy watches Node's own API surface and catches the construction. It is weaker than eBPF nearly everywhere and stronger in exactly that one place, which is why a transcript always says which one watched it.
